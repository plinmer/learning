# 本地跑大模型：入门框架

这份笔记记的是「在自己电脑上把一个大模型跑起来」要准备什么、事情按什么顺序发生。以这台 Mac（Apple M1 Pro、32GB 内存、macOS 14.4）和 `Qwen2.5-3B` 为例，不展开每个启动参数。

## 先建立一张图

本地推理就三块东西，缺一块都跑不起来：

```text
你的问题
   │
   ▼
本地服务（一个一直开着的程序，听 127.0.0.1:8000）
   │
   ├── 推理引擎：vLLM，负责加载模型、排队、生成文字
   └── 模型权重：Qwen2.5-3B 的那一份文件，大约 6GB
   │
   ▼
一段回答
```

浏览器或 `curl` 只是发请求的客户端。真正干活的是本机上的服务进程。服务关了，模型就「不在跑」了；权重还在硬盘上，下次可以再启动。

## 这台机器能走哪条路

vLLM 最常见的跑法是 NVIDIA 显卡。这台 Mac 没有 NVIDIA 显卡。它有 M1 的核显，但要用那块 GPU，需要另一套叫 vLLM-Metal 的组件，而且要求 macOS 15。当前系统是 macOS 14.4，所以这次走的是 **CPU 版 vLLM**：模型在 CPU 上计算，能用，速度大约每秒几个 token，适合学习和试一句对话，不适合高并发。

换一台带 NVIDIA 显卡的 Linux 机器时，框架不变，只是引擎换成 GPU 版，同样的模型会快很多。

## 准备什么

按顺序就四步。

1. **Python 环境**  
   用一个单独的虚拟环境，不要用系统自带的 Python。这台机器还要注意：解释器必须是苹果芯片的 arm64，Intel 版的 Python 装不上这个包。现在用的环境在仓库里的 `.venv`（Python 3.12）。

2. **推理引擎**  
   安装能在这台 Mac 上运行的 vLLM（CPU 预编译包）。仓库里的源码主要是给 GPU 编译的，克隆下来不等于已经能跑。

3. **模型权重**  
   模型名字（例如 `Qwen/Qwen2.5-3B-Instruct`）只是一个地址。第一次启动会把大约 6GB 的文件下载到本机缓存（`~/.cache/huggingface`）。下完之后，服务读的是本地文件。国内网络直连 Hugging Face 经常很慢，可以用镜像，断了可以续传。

4. **把服务拉起来，再发一句话**  
   启动 `vllm serve`，等它加载完权重。然后向 `http://127.0.0.1:8000/v1/chat/completions` 发一条对话请求。这就是一次完整的闭环。

## 和「已经做完的事」怎么对应

| 框架里的一块 | 这台机器上的实际情况 |
| --- | --- |
| 电脑 | M1 Pro，32GB 统一内存，macOS 14.4 |
| 引擎 | CPU 版 vLLM，装在 `.venv` 里 |
| 模型 | `Qwen/Qwen2.5-3B-Instruct`，权重已在本地缓存 |
| 对外接口 | 本机 `127.0.0.1:8000` 上的 OpenAI 兼容接口 |
| 现在的状态 | 服务进程不会一直留着，关掉终端或重启后需要重新启动 |

服务没在听 8000 端口，就说明模型当前没在跑。权重还在，重新执行启动命令即可，不必再下载。

## 最小闭环长什么样

概念上只有两步，细节参数以后再补：

```bash
# 1. 在虚拟环境里启动服务（第一次会下载权重）
vllm serve Qwen/Qwen2.5-3B-Instruct

# 2. 另开一个终端，发一句话
curl http://127.0.0.1:8000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"messages":[{"role":"user","content":"你好"}]}'
```

在这台 Mac 上，启动时还要告诉引擎「用 float16、先不要做 GPU 那套编译」。那是适配 CPU 的开关，不影响上面这张图：仍然是「服务 + 权重 + 一次 HTTP 请求」。
